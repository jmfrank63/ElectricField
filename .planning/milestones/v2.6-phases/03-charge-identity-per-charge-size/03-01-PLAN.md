# Plan 03-01: Charge Identity & Per-Charge Size

**Phase:** 3 - Charge Identity & Per-Charge Size
**Mode:** mvp (auto-mode; owner standing instruction: always take the recommended answer)

## Objective

Every charge carries a stable id, an editable name and its own drawn size (`ef::Charge`,
`ef::PresetCharge`, persisted in collections + sessions, editable in the panel and via the API);
the Options charge size becomes the DEFAULT for new charges and the fallback for charges without an
override; hovering a charge shows its name as a tooltip. Physics untouched: `sizePx` is a draw
property only, and the field/potential code never reads it (CHARGE-01, CHARGE-02).

## Pinned Decisions (do not re-litigate during execution)

1. **Charge-line field order** (both configs.cpp and session_file.cpp, symmetric):
   `charge = value, x, y, sizePx, id, name`. Parse accepts **exactly 3 fields (legacy) or exactly
   6 fields (extended) - all-or-nothing after y**. No 4/5-field partial forms (this refines
   03-CONTEXT's "extended 4-6 field" wording): writers always emit 6, so partial forms only come
   from hand edits, and a strict grammar is unambiguous (a 5th field could otherwise be read as id
   or name). Any other arity = skipped charge, counted as today.
2. **Stale vs dirty:** name/size edits mark the tab **dirty only** (they are collection-visible
   state for the unsaved-changes prompt) and update the scene in place immediately. They never set
   `stale`, never arm `pendingRecalcAt`, never trigger recalculation - the drawn lines are not a
   function of name/size. `setChargeSize` syncs `scene.charges[i].sizePx` (canvas redraws at once);
   `setChargeName` needs no scene copy (the tooltip hit-tests `field.charges`). Undo/redo ride the
   existing `HistoryEntry{ChargeSystem}` snapshots for free - doctests verify, not assume.
3. **Names:** charges store `name = ""`; the display name `"Charge N"` (N = 1-based index) is
   DERIVED at display time by one helper. Nothing ever writes literal "Charge N" into the model or
   a file - lean persistence, one derivation site (this supersedes the "Workspace assigns names"
   phrasing in the discussion notes; the model decision "empty = derived display" wins and
   satisfies CHARGE-02 identically).
4. **addCharge plumbing:** `bool addCharge(Tab&, ef::Vec2, int value, float defaultSizePx = 0.f)`.
   addCharge assigns the id itself (`nextChargeId` = max over the system + 1 - identity is model
   logic, doctest-able) and stores `defaultSizePx` after validating (0 or 2..120; anything else
   degrades to 0 = inherit). The CALLER passes the Options default: `env.options->draw.chargeRadiusPx`
   (ui.cpp canvas + panel) and `options_.draw.chargeRadiusPx` (app.cpp `charge.add`). Existing
   call sites keep compiling via the default argument.
5. **hitCharge signature:** `int hitCharge(const ef::ChargeSystem& field, ef::Vec2 world,
   double pixelsPerUnit, double defaultRadiusPx)` plus `inline constexpr double kEditorHitSlack =
   0.05` (world units). Per-charge bound = `(c.sizePx > 0 ? c.sizePx : defaultRadiusPx) /
   pixelsPerUnit + kEditorHitSlack` - identical to today's `kEditorHitRadius = 0.30` at the
   defaults (25 px / 100 ppu + 0.05 slack), per-charge everywhere else. `pixelsPerUnit <= 0`
   degenerates to 1.0. Radius-px and ppu must be in the SAME space: ui.cpp passes
   `view.pixelsPerUnit` (device) with `defaultPx * env.k`. `kEditorHitRadius` is deleted.
6. **Id persistence:** open paths preserve ids that arrived from a 6-field line; only `id == 0`
   charges get assigned (monotonic max+1 within the system) by `editor::assignChargeIds`, called
   from `Workspace::open` (after `makeSystem` -> presets get 1..N), `openUser` and `openRestored`.
   `makeSystem` itself stays field-carrying (id 0) so ef-cli parity output is untouched.
7. **app.state dump:** `charges=v,x,y,sizePx,id,displayName;...` with the EFFECTIVE name
   (substring-compatible: old scripts expecting `charges=1,0.5,0` still match the prefix).
8. **API:** `charge.name <i> <name...>` - index REQUIRED (unambiguous next to a quoted name);
   remaining tokens joined with single spaces; ',' stripped (same rule as the mutator; empty name
   allowed = back to derived). `charge.size <i> <px>` - 0 or 2..120, else
   `error: charge size must be 0 or 2-120`. Both realtime-edit like `charge.move` (dirty, no stale).
9. **zoomCeiling stays on the Options default** (`dotPx` in ui.cpp/app.cpp unchanged): the ceiling
   is a numerics rule about the floored seed circle, not a per-charge property. Per-charge sizes
   feeding the ceiling is out of scope.
10. **Tooltip is GUI-only** (hover state cannot be scripted): covered by UAT, not the script suite.

## Deliverables

1. `ef::Charge` + `ef::PresetCharge` gain `std::uint64_t id = 0`, `std::string name`, `float
   sizePx = 0.f` (trailing members with default initializers, so every existing aggregate init
   compiles with old semantics); `ef::SceneCharge` gains `float sizePx = 0.f`; every
   construction/conversion site carries the fields through (the mechanical sweep).
2. Extended charge lines in BOTH `app/configs.cpp` and `app/session_file.cpp` - write 6 fields,
   parse 3-or-6, comma-free names, UTF-8 byte-passthrough - with round-trip doctests (legacy +
   extended + name edge cases).
3. Editor core: `setChargeName` / `setChargeSize` (dirty-not-stale), `nextChargeId` /
   `assignChargeIds`, `chargeDisplayName`, per-charge `hitCharge` - all doctested (semantics, id
   no-reuse incl. after undo, hit ordering with overlapping different-size charges).
4. GUI: Name + Size rows in the editor panel, hover tooltip on the canvas, selection ring at the
   effective radius, Options charge-size help text = "default size for new charges".
5. API + oracle + docs: `charge.name` / `charge.size`, extended `app.state` charges dump, script
   `45-charge-identity.efscript`, api.md + README updates.

### Task 2: Extended charge lines - configs.cpp + session_file.cpp, symmetric, with round-trip doctests

  `charge = <value>, <x>, <y>, <sizePx>, <id>, <name>` - x/y/sizePx via `%.10g`, id via `<<`,
  name written raw AFTER stripping every ',' (same erase-remove pattern the section/tab titles use

  value/x/y validation exactly as today, then pin Decision 1: `parts.size() == 3` -> legacy

  `ini::parseDouble` (finite), id with `ini::parseIntBounded(parts[4], 0, 1000000000, ...)`, name
  as the raw (already comma-split-trimmed) part 5; ANY other arity -> `++skippedCharges` /
  `++r.skippedCharges` (invalid line, never fatal). Names may contain spaces (splitCsv only splits
  on ','); non-ASCII passes through byte-for-byte (no transformation anywhere).

  - legacy 3-field text parses with zeros (existing tests already pin this - keep green);

## Risks

- **The sweep is completeness-critical, not compile-critical:** every existing aggregate init
  keeps compiling via the trailing NSDMIs, so a MISSED conversion site fails silently (dropped
  id/name/size on save). Task 1's grep gate + the Task 5 round-trip script are the two nets; if a
  site surfaces later, it will be one of the `PresetCharge{` / `SceneCharge{` literal rebuilds.
- **`PresetCharge` becomes non-trivially copyable** (std::string member): it lives in vectors in
  hot-ish paths (save/merge) - copies are per-user-action, not per-frame; no perf concern, but do
  not introduce per-frame PresetCharge copies in drawCanvas.
- **Hit-test behaviour change is subtle:** at defaults the bound is byte-identical (0.25 + 0.05 =
  0.30), but zoomed views now scale each charge's bound with its own size; the overlap doctests in
  Task 3 pin the ordering so nearest-wins stays intuitive for nested charges.
- **`app.expect` substring reliance:** the extended dump must keep the `v,x,y` prefix exactly
  (separator discipline: always ','), or existing scripts 40/41/42/43 break - the suite run in
  Task 5 catches any drift.
- Tooltip coverage is UAT-only (headless scripts cannot hover) - accepted, recorded here and in
  the phase summary.
