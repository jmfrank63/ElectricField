# Plan 01-01: Collections UX Fixes (REC-02 recents seeding, COL-10 visible removal)

**Phase:** 1 - Collections UX Fixes
**Mode:** auto (owner standing instruction: always take the recommended answer; decisions pre-made in 01-CONTEXT.md)

## Objective

Recent Collections shows what was opened even when starting fresh: a pre-recents session pointer
(`collection = X`, no `recent` lines) seeds X into the list at startup, the pointer's collection line
is never blanked, and the pointer is rewritten at quit. In the configuration chooser, removing the
selected configuration is a visible `Remove...` button (existing confirmation flow; right-click and
`config.remove` unchanged). Requirements: REC-02, COL-10.

## Deliverables

1. Pure, doctested seam in `src/app/session_file.{hpp,cpp}`: `ParsedSession`/`SavedSession` gain
   `hasCollection` (true only when a non-empty `collection =` value was parsed - the parser's
   `"Original"` default must stay distinguishable), plus `seedRecents(recents, collectionKey)`
   (insert-at-front if absent, cap 10) and a `kMaxRecents = 10` constant.
2. REC-02 wiring in `src/gui/app.cpp`: `App::init` seeds recents from the pointer's collection when
   `hasCollection` and the file resolves via `App::collectionFile` + exists; `writeSessionPointer`
   preserves a previously stored collection name when no collection is open (read-modify-write);
   `App::runInteractive`'s shutdown block rewrites the pointer at quit (and stops downgrading it to
   `collection = Original` with no recents).
3. COL-10 in `src/gui/ui.cpp` `chooserModal`: a visible `Remove...` button under the list, enabled
   only when the selected row is a configuration, wired to the existing
   `removeConfigName`/`removeConfigOpen` confirm flow.
4. Proof + docs: `tests/scripts/44-recents-seed.efscript` (sandbox pre-seeded with a legacy pointer
   by the harness, as SC1 demands), the CI seeding lines in `.github/workflows/ci.yml`, doctests in
   `tests/test_session_file.cpp`, README Collections bullet and docs/api.md notes.

## Tasks

### Task 1: REC-02 pure seam - `hasCollection` flag + `seedRecents` helper + doctests

- **Files:** `src/app/session_file.hpp`, `src/app/session_file.cpp`, `tests/test_session_file.cpp`
- **Action:**
  - In `session_file.hpp`: add `bool hasCollection = false;` to `ParsedSession` (near line 44) and
    `SavedSession` (near line 61), documented as "true only when the file carried a non-empty
    `collection =` value (the struct's `"Original"` default is NOT a stored line)". Add
    `inline constexpr std::size_t kMaxRecents = 10;` and declare
    `std::vector<std::string> seedRecents(std::vector<std::string> recents, const std::string& collectionKey);`
    - `collectionKey` is the UTF-8 path of the pointer's collection file, or empty when there is
      nothing to seed (no explicit line / file missing). Recents entries are full paths, so
      membership is compared against `collectionKey`, never a bare name.
  - In `session_file.cpp`: in `parseSession`, set `r.hasCollection = true;` inside the existing
    `if (!value.empty()) r.collection = value;` branch (line ~105). In `loadSessionFull`, copy the
    flag to `SavedSession`. Implement `seedRecents`: empty key -> return unchanged; key already in
    the list -> return unchanged (order intact); otherwise insert at the front and truncate to
    `kMaxRecents`.
  - In `tests/test_session_file.cpp` extend the recents TEST_CASE (line ~174) and the collection
    TEST_CASE (line ~104) with: (a) explicit `collection = X` -> `hasCollection` true; blank line and
    absent line -> false (parse AND `loadSessionFull` round-trip); (b) `seedRecents({}, key)` ->
    `{key}`; (c) key already present -> list unchanged; (d) empty key -> unchanged; (e) seeding into
    a non-empty list inserts at the front; (f) seeding into a full 10-entry list yields 10 entries
    with the seeded key first.
- **Verify:** `zig build test` (new doctests green, suite green)
- **Done:** `hasCollection` distinguishes a genuinely stored collection line from the parser default;
  `seedRecents` is covered by doctests for all six cases.
- **Commit:** `feat(v2.6): recents seeding seam - hasCollection parse flag + seedRecents helper (phase 1)`

### Task 2: REC-02 wiring - seed at startup, never blank the pointer, rewrite at quit

- **Files:** `src/gui/app.cpp`
- **Action:**
  - `App::init` (lines 221-223): capture the pointer load once
    (`const efapp::SavedSession pointer = efapp::loadSessionFull(sessionPath_);`); build
    `seedKey`: only when `pointer.hasCollection`, resolve `collectionFile(pointer.collection)` and,
    if the file exists, use its `u8string()`; then
    `recents_ = efapp::seedRecents(pointer.recents, seedKey);`. (A fresh sandbox has no
    session.ini -> `hasCollection` false -> no seed; script 42's `app.expect recents=` stays green.)
  - `App::writeSessionPointer` (lines 1231-1237): when `currentCollection_` is empty AND
    `sessionPath_` exists, read-modify-write:
    `const efapp::SavedSession prev = efapp::loadSessionFull(sessionPath_);` and use
    `prev.hasCollection ? prev.collection : std::string()` as the written collection value, so a
    stored name (e.g. the pre-h26 pointer's `Original`) is never blanked. When
    `currentCollection_` is non-empty it wins as today. (The exists gate keeps a first-ever pointer
    write blank instead of inventing `Original`.)
  - `App::runInteractive` shutdown block (lines 511-526): keep building `saved`, then replace the
    single 2-arg `efapp::saveSession(sessionPath_, saved, err)` write with:
    (a) collection open -> `saveSessionNow()` (tabs to `Sessions/<name>.ini`, COL-09's native path;
    also preserves grid/autocalc which the inline dump drops) ; (b) no collection but tabs open
    (preset/empty tabs) -> `efapp::saveSession(sessionPath_, saved, std::string(), recents_, err)`
    so the tabs still migrate at next start while the recents survive the dump (blank collection
    line -> `hasCollection` false -> no spurious seeding); then ALWAYS call `writeSessionPointer()`.
    Do NOT simply append `writeSessionPointer()` after the old dump: it writes an empty tab list and
    would erase the just-dumped tabs (tab-restore regression).
- **Verify:** `zig build && zig build test`, then the script proof from Task 4's script:
  `rm -rf /tmp/ef-44 && mkdir -p /tmp/ef-44 && printf 'collection = Original\n' > /tmp/ef-44/session.ini && ./zig-out/bin/ElectricField --script tests/scripts/44-recents-seed.efscript --user-dir /tmp/ef-44 --out /tmp/ef-44/out.log`
  (non-zero exit = failure). The quit-time rewrite itself is interactive-only: note it for UAT (see Risks).
- **Done:** a legacy pointer seeds `recents=Original` in app.state on start; modern pointers are
  untouched; the pointer written at quit always carries the current recents and never blanks a
  stored collection name; open tabs still restore.
- **Commit:** `feat(v2.6): seed recents from the session pointer, never blank it, rewrite it at quit (phase 1)`

## Risks

- **Pointer-vs-tabs write order at quit:** `writeSessionPointer` writes an empty tab list; calling it
  naively after the old session.ini tab dump would silently break tab restore. Task 2's branch
  (saveSessionNow when a collection is open; dump only for collection-less preset tabs) is the
  mitigation - the executor must not "simplify" it back into a single dump + pointer write.
- **Parser default masks the legacy shape:** `parseSession` returns `"Original"` for a blank/absent
  collection line, so seeding on "non-empty value" alone would seed `Original` on fresh sandboxes
  and blank post-h26 pointers (script 42's `app.expect recents=` would fail). The `hasCollection`
  flag is the discriminator; skipping it re-introduces the defect.
- **Quit-time rewrite is not script-reachable:** `runScriptMode`'s shutdown (app.cpp ~2014) is a
  different path and stays as-is per the CONTEXT decision (runInteractive only). SC3 is covered
  interactively (UAT above); the doctests pin the never-blank inputs (`hasCollection`,
  `loadSessionFull` round-trip).
- **Chooser focus/nav regressions:** the Remove... button must not take default focus (keyboard
  Up/Down + Enter on the list rows is pinned behaviour); disabled state must be a real
  `BeginDisabled` so nav skips it.
