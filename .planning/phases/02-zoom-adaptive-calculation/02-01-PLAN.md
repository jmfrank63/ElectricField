# Plan 02-01: Zoom-Adaptive Calculation

**Phase:** 2 - Zoom-Adaptive Calculation
**Mode:** auto (owner standing instruction: always take the recommended answer)
**Note:** planned inline by the orchestrator after two silent gsd-planner subagent failures; the derivation below is the plan of record.

## Objective

Zooming into a charge no longer shows the uncalculated disk around it: seed and hit radii adapt to the
view (the seed circle is ~2 px on screen when zoomed in, floored for numerics), a zoom-settled tab
recalculates automatically (debounced, never stale/dirty/undo), sub-pixel-spaced equipotential rings are
not posted, and the zoom-in ceiling rises to where the drawn charge still covers the seed circle.

## Derived design (the numbers)

- Adaptation engages ONLY above the reference ppu: `adapt = viewScale > 100` (ComputeParams::kRefPpu =
  pixelsPerUnit = 100). Below/at it, every value is exactly today's -> the default view and ef-cli are
  bit-identical (ef-cli never sets viewScale).
- `seedRadius()`: adapt>1 ? clamp(kSeedPx / viewScale, kMinSeedWorld, 0.25) : 0.25, with kSeedPx = 2.0,
  kMinSeedWorld = 0.01 (= 10x the near-field step 0.001: keeps h/r <= 0.1 for fixed-step methods).
- `hitRadius()`: adapt>1 ? clamp(kHitPx / viewScale, kMinSeedWorld, 25/1.5/100) : legacy, with
  kHitPx = chargeRadiusPx / 1.5 = 16.67 (endpoints stay behind the 25 px drawn dot: at the ceiling the
  seed is the binding constraint, see below).
- Equipotential ring gate (in shouldPostEquipotential, after the existing label logic): a ring is posted
  only when its on-screen spacing along the line is at least kRingPx = 1.25 px. Spacing dr = dV/|E| with
  dV = interval -> post iff `|E(point)| * kRingPx <= interval * viewScale` OR adapt<=1 (legacy). |E| is
  exact for multi-charge fields (no per-charge r needed). Field-line STARTS still hug the charge
  (~2 px), so no white remains; only sub-pixel rings are skipped.
- Ring budget at the ceiling: count/line ~ sqrt(q * viewScale / (kRingPx*interval)): at viewScale 2500,
  q=2 (worst preset) ~ 200/line vs ~40 today at zoom 1 -> bounded, ~2.5 ms/line Euler - fine.
- Ceiling: the drawn dot (25 px default) must cover the floored seed circle (0.01 world):
  viewScale_max = 25 / 0.01 = 2500 -> `kMaxPpu = 2500`. zoomCeiling(minCanvasPx, ppuBase) becomes
  `clamp(kMaxPpu / ppuBase, kZoomMin, kZoomMax)` with kZoomMax raised 20 -> 40 (at k=1: zoom <= 25;
  the canvas-min-side rule of h25 is superseded - the user explicitly wants to zoom in now that lines
  adapt; kZoomMin/kZoomMax stay as the outer guard rails). At k=2 HiDPI: zoom <= 20 (unchanged feel).
- Recalc wiring: `Tab` gains `double viewPpu = 0` (the ppu to recalc with) and `double armedViewPpu = 0`
  plus `double pendingViewRecalcAt = -1` (same marker protocol as pendingRecalcAt: -2 = arm next frame).
  drawCanvas: after computing `view`, if the tab is Done and `view.pixelsPerUnit != t.armedViewPpu` and
  `t.armedViewPpu != 0` -> set t.viewPpu = view.pixelsPerUnit, pendingViewRecalcAt = -2; then
  armedViewPpu = view.pixelsPerUnit. `Workspace::viewRecalcTick(now)` (called by App::frame next to
  autoRecalcTick): -2 -> now + kAutoRecalcDelay; due -> t.params.viewScale = t.viewPpu; calculate(serial).
  No stale, no dirty, no undo (calculate path only). The view.zoom API command flows through drawCanvas
  on the next pumped frame - automatic, script-testable.

## Risks

- Fixed-step traces from the floored seed: kMinSeedWorld = 0.01 keeps h/r <= 0.1 (h = 0.001 near field)
  -> direction change per step <= ~0.1 rad for Euler; adaptive methods self-correct. The seed floor is
  the load-bearing constant - doctests pin it.
- The ring gate evaluates E() once more per tracer step (O(charges)): the presets have <= 4 charges;
  negligible.
- finalizer dedup (dedupEquipotentials) sorts by weight-centre distance: the gate only REMOVES rings;
  dedup is unaffected.
- Session/undo: viewRecalc uses calculate() only; no history entries, no dirty. A mid-recalc edit keeps
  working (the session restart path is the existing calculate one).
- armedViewPpu starts 0 -> the first frame never arms (no spurious recalc on tab open).
