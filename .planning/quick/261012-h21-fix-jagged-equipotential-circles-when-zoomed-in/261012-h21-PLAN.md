<objective>
Fix jagged equipotential circles when the view is zoomed in: the drawn curve resolution must adapt to the zoom, without recomputing.

Purpose: trace points are thinned against fixed pixel thresholds evaluated at the internal constant 100 px/unit scale (tracer.hpp addPoint: dif >= 8/64/256 px by world-length band). After finalize() runs adjustForBezier, the ScenePath carries on-curve anchors at indices 0,3,6,... (plus 1-2 trailing straight-line points) with fitted control points between. Anchor spacing is therefore fixed in world units (~0.24 units for near-origin traces, i.e. 24 device px at the default view) while view zoom ranges up to 100 x k x zoom = 8000 px/unit (k in [0.75,4], zoom in [0.05,20]). Zoomed in, the anchors stretch to hundreds of pixels apart and equipotential circles render as visible polygons. The fix must live at draw time, where view.pixelsPerUnit is known: zooming must not trigger a recompute storm.

Output: zoom-adaptive Catmull-Rom refinement in drawPath + adaptive polar grid circle tessellation in src/core/ef/scene.cpp, with doctest coverage in tests/test_scene.cpp.
</objective>

<approach_note>
Evaluated per the item's "evaluate, don't assume" directions:
- (a) Record denser at trace time: rejected — recording every solver step or 4-8x denser thinning multiplies memory on pathological traces (dipole traces allow 5M steps; ScenePath copies all points in buildScene), changes every default-view render and the fitted-cubic data pipeline, for no visual gain over draw-time refinement at the zoom levels users actually reach.
- (b) Smooth/refine at draw time: CHOSEN — pure view-side change, zero recompute, zero data change, zero memory regression, and all four backends (GUI, PNG, SVG, PDF) inherit it through drawPath.
- (c) Re-trace lazily per zoom band: rejected — a recompute path triggered by zoom is explicitly out (recompute storm).
- (d) Combination: unnecessary once (b) is in; revisit only if extreme-zoom fidelity complaints follow (draw-time smoothing is bounded by anchor density, see Task 1 note).

Rendering mechanics that make (b) sufficient: each backend tessellates a cubic smoothly by device size (ImGui auto-tessellation at CurveTessellationTol 0.3, SVG/PDF delegate to their viewers). The jaggedness is the tangent discontinuity at segment joins plus the coarse anchor sampling — exactly what interpolating Catmull-Rom through the anchors removes, at a resolution that follows the zoom.
</approach_note>

In drawPath (src/core/ef/scene.cpp, anonymous namespace), add a zoom-adaptive refinement branch selected by a device-space gate, restructuring the function minimally so both branches share one culling/flush loop.

Step 1 — Restructure for two branches: after the existing world-to-device mapping into dev[], build a list of 4-point cubic groups plus optional trailing points, then run ONE shared culling/flush loop (the current per-group vis.intersects check, run accumulation with shared endpoints, culledAny tracking, and flush(closed && !culledAny) rule — behavior preserved exactly). The legacy branch produces groups exactly as today (dev[3k..3k+3]) with the trailing 1-2 points handled as today; the refined branch produces Catmull-Rom groups (step 2) and has no tail.

Step 2 — Anchor extraction: the on-curve anchors are the device points at indices 0,3,6,... plus the trailing 1-2 straight-line points (indices greater than 3*segs, where segs = (n-1)/3). Closed figures: when path.closed is true and the last anchor equals the first anchor (exact device equality — the loop closure point, which buildScene guarantees as world front==back), drop the final anchor and treat the anchor list as periodic (wrap neighbor indices); otherwise treat it as open.

Step 3 — Gate: add a file-local constant kRefineAnchorChordPx = 48.0 (comment: 2x the ~24 px default-view anchor spacing from the 8 px recorded thinning x 3; below it the legacy fitted cubics render sub-pixel smooth, above it corner kinks become visible). Take the refined branch iff the anchor list has at least 2 points AND the largest consecutive anchor chord exceeds kRefineAnchorChordPx. Consequence (intended): near-origin traces at the default view keep the exact legacy geometry (all existing exact-output tests keep passing unchanged); zoom >= ~2x refines; far-from-origin trace bands (64/256 px thinning => >=192 px anchor chords) refine even at the default view, which is the same fix applied where those bands are already coarse.

Step 4 — Refined emission (uniform Catmull-Rom through the anchors, emitted in the existing 4-point group layout so the Painter contract and every backend stay unchanged): for each consecutive anchor pair (A[i], A[i+1]) emit the group (A[i], c1, c2, A[i+1]) with c1 = A[i] + (A[i+1] - A[i-1]) / 6 and c2 = A[i+1] - (A[i+2] - A[i]) / 6. Neighbor indices wrap for the periodic case; for open paths mirror the ends: before the first anchor use 2*A0 - A1, after the last use 2*A[m-1] - A[m-2]. Use double precision like the surrounding mapping code. There are no divisions by computed quantities (only the constant /6), so no degeneracy fallbacks and no new NaN paths; coincident-anchor groups fall out naturally and are harmless in every backend (same class of degenerate groups the legacy path already emits after adjustForBezier fallbacks). Culling uses the same vis.intersects on each emitted group's 4 points (conservative control-polygon box).

Step 5 — Determinism and scope guards: pure double arithmetic, no transcendentals, no per-length divisions; respects the -ffp-contract=off numerics policy. Do NOT touch tracer.hpp, finalizer.cpp, bezier.hpp, or any backend painter — zooming must not be able to trigger a recompute, and the Painter contract must not change.

Step 6 — Tests in tests/test_scene.cpp (extend the existing file, reuse its Recorder painter):
a. Default-view legacy pin: a multi-group path whose device anchor chords are <= 48 px (points ~0.2 world units apart at ppu 100) renders with stroke points equal to the direct device mapping of the input points and segs == (n-1)/3 — the legacy contract, made explicit.
b. Refined interpolation: build a realistic post-finalize path (points on a circle, run ef::adjustForBezier over a copy) and render at pixelsPerUnit 1000; assert every emitted group's start and end points coincide with the corresponding anchor within 0.01 px.
c. C1 smoothness: on the same rendering, at every interior join the incoming tangent 3*(p3 - c2) equals the outgoing tangent 3*(c1' - p0) within 1e-6 px (exact by construction of uniform Catmull-Rom).
d. Closed loop: a closed equipotential (points around a circle plus the duplicated closing point) fully inside the view renders one stroke with closed == true, passes through the first anchor, and emits no zero-length final group (duplicate closure anchor dropped, periodic wrap).
e. Gate: the same path at ppu 100 takes the legacy branch (assert exact mapping and segs) while at ppu 250 the emitted group endpoints differ from the legacy direct mapping (refinement active).
