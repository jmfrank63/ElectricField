<objective>
Fix v2.5 CFG-04's stale-identity hole: after a tab is renamed, File > Save Configuration (and `config.save`) must update the configuration to the tab's current name — renaming the collection entry in place — instead of saving silently under the old name (in-session) or failing with a lookup error on a name no entry owns (after a restart, where the restored tab derives its source from the renamed title).

Purpose: the tab's name is the user's configuration identity; a save that ignores a rename either strands the charges under a stale name or refuses to save at all.

Output: a unit-testable save decision core in the app layer, App::saveConfiguration rewired onto it, session-file provenance so the rename link survives restarts, and e2e proof in the efscript suite.
</objective>

<approach_note>
Identity model (stated per the assumption-delta checkpoint — evaluated and treated as NOT FIRED: this is a pure bug fix with one consistent identity model):
- The tab's CURRENT base title (efapp::baseTitle of the title) is authoritative for where Save Configuration writes; the trailing " <N>" suffix is the per-name counter, stripped exactly as mergeDirtyTabsInto (app.cpp:1239) and openRestored (workspace.cpp:147) already do.
- Tab::sourceConfig is NOT touched at rename time. It stays "the configuration this tab came from" — the provenance. Renaming at save time reconciles sourceConfig -> current title by renaming the source entry in place (position and other entries preserved). Updating sourceConfig at rename time was weighed and rejected: it would overwrite the very link the in-place rename needs, forcing an append that strands the old entry with stale charges beside the new one. Save-time reconciliation keeps the rename-in-place outcome and needs no workspace changes.
- Foreign-name collision: REFUSE (error pointing at Save Configuration As). The Save-As dialog owns confirmed overwrites (the "Overwrite?" modal, ui.cpp:488); silently destroying another configuration from the plain menu item or the API would be silent data loss. A case-insensitive match of the tab's OWN source entry is not a collision — it respells that entry in place (upsertUserConfig's spelling convention, configs.cpp:153).
- Preset-sourced tabs (sourceConfig == a preset displayName, workspace.cpp:40/147): built-in presets are immutable (reserved names, CFG-03/D-04). Unrenamed: the reserved-name refusal — today this case emits the misleading stale-source lookup error purely because presets are never user configs. Renamed: append a NEW user configuration under the new name (Save-As creation semantics).
- Cross-restart (SES-01): the session file stores titles only today, so a restored tab derives sourceConfig = baseTitle(title) and the old-name link is lost. SavedTab gains an optional `source` line so provenance survives; absent lines (legacy files) keep the derivation, so the format change is backward and forward compatible (the parser already ignores unknown keys).
</approach_note>
