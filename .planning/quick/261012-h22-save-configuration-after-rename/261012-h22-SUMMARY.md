## Decisions Made
- **Own-entry precedence over the reserved check (deviation from the plan's literal step-2 ordering).** The plan's core spec orders the reserved-name check (step 2) before the source/candidate lookups (steps 3-7). Taken literally, that refuses the unrenamed save of ANY tab whose current name matches a preset display name — but the seeded Original collection consists entirely of preset-named user configs, so `config.open Dipole` → edit → Save Configuration would have begun refusing there. That contradicts the plan's own success criterion ("Unrenamed saves behave exactly as CFG-04 shipped") and would disagree with `mergeDirtyTabsInto` (Ctrl+S), which merges into preset-named entries without a reserved check. Implemented instead: the tab's-own-entry match (target == at, case-insensitive) takes precedence and overwrites in place regardless of reservedness; the reserved refusal still fires for every NEW name (renamed tabs, doctest g) and for true preset-sourced tabs whose name has no user entry (unrenamed-preset shape, doctest g'). All eight of the plan's doctest cases pass as specified; the plan's preset truths hold in every case where "preset-sourced" is actually detectable — the seeded Original's preset-named user configs and the built-in presets are indistinguishable by `sourceConfig` alone, and the user-config interpretation is the one coherent with the rest of the save paths.
- **Save-As renames the tab to the saved name.** Discovered via the full-suite run: under the title-authoritative model, a save-as'd tab (source "MyEditor", title still "Empty Configuration 1") would have its next `config.save` rename the user's "MyEditor" entry to "Empty Configuration" — breaking the documented save-as contract and 10-editor's pinned assertions. Renaming the tab at save-as time makes title-vs-source mismatch unambiguous ("renamed since source was established") and fixes a latent cross-restart variant of the same hole.
- **SavedTab.source placed as the struct's last field with a `{}` default.** The plan said "after `preset`" and also "leave sample() untouched" — mutually exclusive, because `sample()` and two more round-trip cases initialize SavedTab positionally, and this toolchain errors (-Wextra -Werror) on missing field initializers. End placement + NSDM keeps every existing test line byte-identical; the ini format is keyed by name, so field order is unobservable.
